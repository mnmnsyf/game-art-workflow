# 2D Static Assets

## Design and splitting

Distinguish full backgrounds, foreground / midground / background layers, sortable sprites, repeating modules, ground tiling textures, and textures for 3D. Make 3D references separately — slices with scene occlusion cannot stand in for them.

Concept art is reviewed for structure, composition, and style; runtime art handles anchors, sorting, and reuse. Propose a split table first: object, use, pixel / game size, perspective, ground point, occlusion layer, transparency / tiling, variant reuse, and missing parts to paint. Produce only after the split plan is approved.

## Generation and processing

- Probe tools first; if missing, let the user choose per tools.md. When using an existing imagegen skill, follow its generate / edit and save requirements.
- Look at the input before editing; separate design reference, style reference, and edit target; state the invariants — don't change doors and windows while fixing the background.
- Single pieces keep a complete silhouette with safe padding and a fixed camera and light direction; module borders, corners, and repetition rhythm are designed for runtime use.
- A checkerboard painted into RGB is not real alpha. Test white / dark fringes and semi-transparent edges on black, white, and colored backgrounds; don't erase soft edges with a harsh threshold. `python scripts/alpha_check.py <png> --out review/` does it in one go: it reports whether alpha exists, suspected fake checkerboard, semi-transparent ratio, and edge margin, and writes composites on three backgrounds.
- Paint in occluded areas and the background behind removed objects. Cropping does not produce furniture that was hidden; slices with ground shadows cannot be used directly as standalone props.
- Fix anchors, pixel density, and ground points; keep the original and output cropping, padding, and background removal as new versions. Choose filtering, compression, and mipmaps by art style and actual size.

## Textures

Separate base color from PBR data channels. Make a 2×2 or 3×3 repeat preview first (`python scripts/tile_preview.py <png> --grid 3`, which also reports left/right and top/bottom seam error and low-frequency brightness gradient), check seams, brightness gradients, and repeating features, then look again at actual UV scale. With dynamic lighting, don't bake directional light and large shadows into the base color.

Base color uses the correct color space; normal, roughness, metallic, AO, and masks are data textures. Never claim to accurately recover real PBR from a single image; if the tool only generates base color, say so. Atlases keep edge extension and mipmap padding to avoid bleeding; vegetation cards also need checks for clipping, two-sidedness, shadows, overdraw, and distant shimmer.

## Review and integration

Review the concept first, then the actual cut-outs / tiling. Show whichever apply: the full assembly, background tests of each piece, the repeat preview. In game, watch a character walk in front of and behind furniture, parallax, and ground contact; collision covers the footprint, not the whole transparent image rectangle. Split off a foreground part that occludes the character when needed.

Deliver the approved original, editable sources that actually exist, runtime PNG / atlas / textures, anchor sizes, source license, version, and engine resources. Without a layered project file, never present a PNG as a PSD.
