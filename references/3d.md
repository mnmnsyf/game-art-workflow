# 3D Static Assets

## Route and references

For a generated model, run the whole route with [the model chain](model-pipeline.md) (`model_job.py`); this file holds the rules it applies.

At G1 choose generation, traditional / procedural, or hybrid. Regular buildings, exact openings, module interfaces, and interiors usually need controlled structure; compare credits, cleanup time, and reuse. No style guarantees a generated model needs no cleanup.

Reference images: a complete single object, clear volumes, simple background, even soft lighting — don't reduce the design to a box just to cut noise. Multi-view sets must agree on design, proportion, orientation, door/window count, and materials; randomly generated front and back views are not reliable multi-views, and a collage cannot be uploaded as a single object. Keep the actual inputs and their hashes.

G2 reviews the reference first, then generation; after generation show front, back, bottom, and key openings — you cannot judge a GLB by reading it, so render it: `blender -b -P scripts/blender_views.py -- raw.glb --out review/raw_views` writes seven views and `stats.json` (world size in meters, triangles, materials). Many generators export every model about one unit tall; set the real size from the manifest's `in_game_size`, not the generator. Show the views, and do dependent processing only after the model is approved. Stop and wait at each of these reviews; only an explicit written delegation from the user lets the agent review on their behalf.

Render the exported GLB itself, not only a supplier preview. `render_asset.py` produces seven textured and matching seven clay views (incl. a front three-quarter for concept comparison) plus mesh/UV/texture statistics; assemble them with `contact_sheet.py`. Clay views help separate geometry problems from material artifacts. Its front/back labels use Blender axes, not an inferred architectural facade. See [Production helpers](production-tools.md). Keep single views and statistics in scratch; preserve the contact sheet actually shown at G2. Open-edge counts are diagnostic, not universal rejection rules for intentional cards or open meshes.

## Four phases

| Phase | Work | Acceptance |
| --- | --- | --- |
| A0 Raw output | Download and keep the raw model and textures | Silhouette, back, open shells, fragments, thin parts, UVs, materials |
| A1 Faithful import | Only units, origin, orientation, correct material wiring | Same-angle / similar neutral-light comparison, full geometry and PBR |
| A2 Optimization branch | Decimation, LOD, and texture budget by actual screen error | Silhouette, UV, normal, and material information transferred; no silent design changes |
| A3 Game integration | Placement, collision, occlusion, lighting, existing interfaces | Actual camera and character movement, door steps, clipping, grounding |

If A0 fails, compare repair, route change, and regeneration instead of blindly buying post-processing. A2 is not mandatory: if the raw output fits the budget, don't decimate for the sake of process.

## Local cleanup

Normalize size and ground origin by the overall world bounding box; keep parts, loop UVs, material slots, and color spaces. Record coordinates, units, and export settings. Skeletons, animation, and shape keys must not be baked away by static cleanup. Route such inputs to [Character production](characters.md); the skinned-character steps require separate capability and deformation checks.

Compare triangle count / topology, geometric positions, UVs, and every texture connection. Identical bytes can be proven by hash; when encoding changed, compare decoded pixels (`python scripts/compare_images.py src.png out.png`; a max diff of 0 means pixel-identical). Also use it for side-by-side DCC vs. engine screenshots from the same angle. Topology reordering needs tolerance-based surface / corner correspondence, not just vertex counts; UVs existing does not prove they map correctly.

UV seams may be split vertices at coincident positions; decide whether to weld before decimating and keep loop attributes — never weld thin sheets and hard edges unconditionally. After removing a roof, check the cross-section; caps / liners must not cover recessed window glass. Never hide conversion errors by disabling normals, dropping metallic-roughness, or repainting base color.

## Collision and display

Build collision separately and choose by use: simple shapes, convex decomposition, or static trimesh — don't default to a whole-building convex hull that blocks the door. Treat doors, windows, steps / ramps, and seating zones individually. Physical gentle slopes need a visible transition so feet don't float.

Modules: check grid size, pivot, seams, corners, and material repetition; vegetation: check cards, two-sidedness, shadows, and LOD. Occlusion changes only the necessary display and keeps physics and PBR. Engine optimizations like Nanite are not a default-on switch.

Deliver the raw model, project files that actually exist, runtime model and textures, comparisons, sources, and check scope. DCC renders do not replace the actual engine result.
